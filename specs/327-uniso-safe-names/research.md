# Research - 327-uniso-safe-names

## R1 - Which rule

- Decision: feature 087's rule applied to one name (`\` and `/` are characters of the name, so they
  become `_` instead of splitting it) - exactly `SalSuspCleanRockRidgeName` of feature 326.
- Rationale: each of these file systems stores one name per directory entry; a separator inside it
  is never a path step. Using `SalArcCleanItemPath` (the path form) would split `..\..\x` into
  components and drop `..` - a name would lose part of itself, and a folder `a\b` would become two.
- Alternatives: the path form (rejected, above); dropping unsafe entries (rejected: the item says
  "renamed, never dropped").

## R2 - Where the rule lives

- Decision: `src/common/salarcname.h` (feature 087's header, already the home of the rule's device
  name test) gets `SalArcCleanItemName`; `salsusp.h` keeps `SalSuspCleanRockRidgeName` as a wrapper of
  the same detail function with its refusal when the prefix does not fit (feature 326's contract and
  its fallback to the plain ISO 9660 name stay).
- Rationale: one implementation; header-only for the plug-in (precompiled header rule).

## R3 - A device name whose `_` prefix does not fit

- Decision: the first character becomes `_` (an ASCII letter of `con`, `prn`, `aux`, `nul`, `com`,
  `lpt`), the name keeps its length.
- Rationale: never cut, never dropped (item). Reachable only near the buffer's end (a plain ISO 9660
  identifier grown by `EnsureU8Name` to 520 bytes, a 768-byte HFS+ name).

## R4 - The sites (enumerated by grep of `AddFile(` / `AddDir(` / `DupStr` / `SalPathAppend` in
`src/plugins/uniso`)

| Site | Name from | Before |
|---|---|---|
| `iso9660.cpp` `ListDirectoryRe` folders, Joliet | `ConvJolietName` | none |
| `iso9660.cpp` `MakeListedName` (ISO 9660 folders, ISO 9660 / Joliet files) | identifier / Joliet | Rock Ridge only |
| `udf.cpp` `ScanDir` | `ReadFileIdentifier` / `DecodeOSTACompressed` | none |

| `xdvdfs.cpp` `ScanDir` | entry bytes | none |
| `udfiso.cpp` `ListDirectory` | PVD / LVD volume identifier, `CHFS::GetRootName` | none |
| `AddBootRecord`, `audio.cpp`, `Session NN` | generated by the plug-in | safe already |
| `UnpackFile` of `iso9660`, `udf`, `hfs`, `xdvdfs`, `rawfs` | `fileData->Name` (listed) | joined as is |

The folder path a reader descends with is the same buffer it lists (`strcat(path, dirName)` after
`AddFileDir`; `newPath` in UDF; `fi->name` in HFS), so cleaning before `AddFileDir` covers both.
`uniso.cpp` `UnpackArchive` / `UnpackOneFile` / `ExtractAllItems` build target paths from listing
names only.

## R5 - The fit check of feature 326

`ListDirectory`'s fit pass calls `ListDirectoryRe` too, so it sees the same cleaned names as the real
pass (one more byte for a device name prefix) - consistent.
