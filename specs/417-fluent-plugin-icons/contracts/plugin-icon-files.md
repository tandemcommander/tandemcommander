# Contract: plug-in icons of an icon set (feature 417, extends `specs/416-fluent-icon-set/contracts/icon-set-files.md`)

## Folders (deployed beside `tandemcommander.exe`)

| Set | Standard | Dark variants |
|---|---|---|
| Fluent 2 | `iconsets\fluent\plugins\<id>.svg` | `iconsets\fluent\plugins\dark\<id>.svg` |
| Classic | - (no plug-in icons: every plug-in keeps its own icon) | - |

`<id>`: one of the 31 plug-in ids of `SalIconSetPluginId` (`src/common/saliconset.h`), or `_plugin` (a plug-in
without an icon) / `_pluginfs` (a file system without an icon). Every name exists in both folders; nothing else is
in them.

## Semantics

1. A plug-in is matched by its DLL name relative to the program's plug-ins folder: exactly `<id>\<id>.spl`
   (ASCII case-insensitive). Any other plug-in (another folder, another file name, an absolute path, an unknown
   id) has no set icon and keeps its own.
2. While Fluent 2 is active, every site that draws a plug-in's identity icon draws the set icon of a matched
   plug-in instead: the Plugins bar, the Plugins menu and its submenus, the plug-in lists of menus (configure,
   about, View With), the Plugins manager, the Change Drive menu and the drive bars, the tab of a plug-in file
   system, the drive-list row and the Disconnect-dialog row of an open file system, and the directory line of a
   plug-in file system - **except** the directory line / drive-list row / Disconnect-dialog row of the Folders
   file system, which keep the icon Folders returns (its current folder's).
3. A matched plug-in with a set file counts as a plug-in with an icon in every list (menus show it even when the
   plug-in hands over no icon).
4. Where the program draws its default plug-in icon or default file-system icon, Fluent 2 draws `_plugin` /
   `_pluginfs`.
5. The 416 file rules apply: the dark variant verbatim when usable in the Dark theme, else the standard file adapted,
   else no set icon - and then the site draws exactly what it draws without the set (never an empty slot).
6. A set icon is rendered at the pixel size of the list that shows it; a gray copy is made by today's gray rule of
   plug-in icons.
7. A set icon is never stored: the plug-in icons saved in the configuration are the plug-ins' own.
8. Nothing changes for plug-ins: their interface, their own windows, toolbars and the icons of the items they list.

## Change management

The files are generated by `tools/brand/fluent-icons/gen_fluent_plugins.py` from the package pinned for 416 and
checked by `tools/brand/fluent-icons/check_iconset.py` and `saltests` (`TestPluginIcons417`). A new plug-in id is
added in three places: the generator's table, `SalIconSetPluginId` and a test row.
