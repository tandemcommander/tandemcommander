# Contract: icon set files (feature 416, extends `specs/029-dark-toolbar-icons/contracts/dark-icon-override.md`)

## Sets and folders (deployed beside `tandemcommander.exe`)

| Set | Standard | Dark variants |
|---|---|---|
| Fluent 2 (default) | `iconsets\fluent\<Name>.svg` | `iconsets\fluent\dark\<Name>.svg` |
| Classic | `toolbars\<Name>.svg` | `toolbars\dark\<Name>.svg` |

`<Name>` is the button's name for that set: the `SVGName` column of `ToolBarButtons[]` for Classic; for Fluent 2 the
same with the overrides of `SalIconSetFluentButtonName` (`src/common/saliconset.h`); drive and `..` names from the
same header.

## Semantics

1. Only the active set's folders are read. The Default theme never reads a dark folder.
2. In the Dark theme: a dark variant that parses and has at least one shape is used verbatim; otherwise the standard
   file of the set with the automatic dark adaptation (feature 029); otherwise nothing is drawn and the cell keeps
   what lies below it (Classic raster glyph, or the Windows icon / Classic icon of that site).
3. A file that cannot be parsed never crashes the program and never blanks a cell (the cell is filled only once a
   usable image exists). This makes rule 3 of the 029 contract true.
4. Colours: never use magenta `#FF00FF` or the theme's toolbar background (`#F0F0F0` light, `#2D2D2D` dark) inside a
   glyph - the image list treats them as transparent.
5. A path that does not fit the buffer is refused (the icon is skipped, rule 2 applies), never cut.

## Change management

- The Fluent 2 files are generated by `tools/brand/fluent-icons/gen_fluent.py` from `@fluentui/svg-icons` 1.1.344
  (pinned, see its README) and checked by `tools/brand/fluent-icons/check_iconset.py`; hand edits are allowed but
  must be carried back into the generator.
- The set folders are deployed by `src/vcxproj/!populate_build_dir.cmd`; the installer takes them recursively.
